# Event image delivery and removal rollout

The `events.0007` migration adds card/detail image variants and the staff-reviewed event removal state. Deploy and run migrations before deploying the frontend. Keep the existing Railway worker running: each `process_jobs` tick converts up to four unprocessed uploaded event images to 640 px and 1280 px WebP copies in the configured S3 bucket. New event uploads enter the same queue. The original remains available as a fallback until both variants are ready.

The website uses the card copy for event lists, bookings and tickets, and the detail copy for large event views. Older event records that only contain an external `image_url` are left unchanged; converting those requires an organizer to upload the source image to Mmemme Abia. Do not fetch arbitrary external URLs in the worker.

Check a live phone page in browser Network tools after deployment: compare image transfer sizes and response time on the first and repeat loads. If storage response time remains high after variants are ready, move *public listing artwork* to a dedicated image CDN; Railway buckets are private and currently return signed URLs. Keep private chat and account media protected. The image copies alone do not create a CDN.

Organizers request event cancellation/removal from My Events before the event starts. Pending requests stop new bookings and hide the event from public discovery. Staff review them at Admin → Organizer inbox or Events → Removal requests. Approval archives the event, cancels pending and confirmed bookings, invalidates tickets, and queues a full Paystack refund for each paid booking. The worker submits refunds and tracks Paystack's final status; initiation is not proof that a customer has received the money. Existing payout allocations, used tickets, unreconciled payments, or an event that has started block automatic approval and require staff investigation. The event and payment records remain for audit. Declining a request restores public visibility when the event is otherwise eligible.

Customers can cancel an entire event booking and all tickets in that booking before the event starts. Paid bookings receive a full refund request; individual-ticket partial refunds are not supported by the current one-refund-per-payment model. Organizers may edit future published events, and attendees with active bookings are notified when title, date, time or venue changes. Existing ticket type prices are fixed after creation, including in drafts; organizers can add a new ticket type with a different price. Event capacity cannot be reduced below tickets sold or reserved.
